# Done-test

The agent said "done", and it was not. It meant "I stopped working", not "it works". This skill writes down what done means before the work starts, and checks it before anyone says the word.

## The principles
1. Done is a check, not a feeling. If a stranger cannot answer it yes or no, it is not a check yet.
2. Write the checks before the work. Checks written afterwards describe what was built, not what was wanted.
3. A check you did not run is not a pass. Say it was not run.

## Steps
1. Before any work, write one to three done-tests. Each one is a check a stranger could answer yes or no: "the tests pass", "the page loads on a phone", "the email arrived in the inbox". When it is taste, write "the owner says yes to X", and name X.
2. For each check, say how it will be run (a command, a step to click through, a person to ask). If you cannot run one yourself, say so now.
3. Show the checks and ask "Are these the right checks?" Start only after a yes. If the request already has clear checks, use them and say so in one line.
4. Do the work. If a check turns out to be wrong, say so and agree a new one. Never change it quietly.
5. At the end, run every check. Report each one as:
   - **Pass**, with the evidence: the output, the number, what you saw.
   - **Fail**, with what happened instead.
   - **Not run**, with why, and the exact step the owner can take to run it.
6. Say "done" only when every check passed. Otherwise say what is left.

## Rules
- Never write "done", "works" or "fixed" without the check results next to it.
- Evidence is something the owner could look at, not "I believe" or "it should".
- "The owner says yes" is never a pass until the owner says it.
